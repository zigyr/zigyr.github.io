# Hexo + NexT 个人博客部署流程记录

## 一、GitHub 仓库与本地环境准备

**阶段目标：** 创建 GitHub Pages 仓库，准备本地 Hexo 项目运行环境。

### 1. 创建 GitHub 仓库

在 GitHub 新建仓库，仓库名称使用：

```text
zigyr.github.io
```

这是 GitHub Pages 个人站点的特殊命名规则，后续可以通过 `https://zigyr.github.io` 访问博客。

其他选项保持默认。

### 2. 安装 Hexo CLI

```powershell
npm install -g hexo-cli
```

**作用：** 全局安装 Hexo 命令行工具，使系统可以直接执行 `hexo` 命令。

**结果：** 安装完成，具备初始化 Hexo 项目的条件。

### 3. 初始化 Hexo 项目

进入本地博客目录 `F:\blog`：

```powershell
hexo init .
```

**作用：** 在当前目录初始化 Hexo 项目，下载 Hexo Starter 模板并安装项目依赖。

**遇到的问题一：** 因为之前执行过 `git init`，目录中已经存在 `.git`，导致初始化失败。

先删除原有 Git 仓库：

```powershell
Remove-Item -Recurse -Force .git
```

**结果：** 删除原有 Git 元数据，避免 Hexo 初始化时发生冲突。

再次初始化：

```powershell
hexo init .
```

**遇到的问题二：** 下载 GitHub 资源时受到网络环境影响。

检查本地代理端口：

```powershell
Test-NetConnection 127.0.0.1 -Port 7890
```

配置 Git 代理：

```powershell
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
```

测试 GitHub 连通性：

```powershell
git ls-remote https://github.com/hexojs/hexo-starter.git
```

**结果：** Git 可以正常访问 GitHub。

重新执行：

```powershell
hexo init .
```

项目初始化成功。

### 4. 处理依赖安装问题

初始化过程中出现：

```text
ERR_PNPM_IGNORED_BUILDS
```

**原因：** pnpm 拦截了部分依赖的构建脚本，需要处理构建脚本审批问题。

尝试使用 npm 安装依赖：

```powershell
npm install
```

但 npm 自身在处理依赖时也出现异常。

此时不急于反复安装，先检查项目状态：

```powershell
Get-ChildItem -Force | Select-Object Name, Length
```

检查项目依赖配置：

```powershell
Get-Content package.json
```

检查依赖树：

```powershell
npm ls --depth=0
```

检查 Hexo 版本：

```powershell
npx hexo version
```

**结果：** 虽然 `npm install` 出现异常，但 Hexo 已经能够正常运行。

启动本地服务器：

```powershell
npx hexo server
```

成功启动，说明当前依赖环境足以支持 Hexo 基本运行。

## 二、NexT 主题安装与配置

**阶段目标：** 安装 NexT 主题，建立主题配置文件，并实现博客的基本视觉效果。

### 1. 安装 NexT

```powershell
pnpm add hexo-theme-next
```

**遇到的问题：** 再次出现 `ERR_PNPM_IGNORED_BUILDS`。

先检查主题包是否存在：

```powershell
pnpm list hexo-theme-next
```

检查主题目录：

```powershell
Get-ChildItem .\node_modules\hexo-theme-next
```

**结果：** 发现主题包已经存在于 `node_modules` 中。

修改 Hexo 全局配置：

```powershell
(Get-Content .\_config.yml -Raw) -replace '(?m)^theme:.*$', 'theme: hexo-theme-next' | Set-Content .\_config.yml -Encoding utf8
```

清理并重新生成：

```powershell
npx hexo clean
npx hexo generate
```

**遇到的问题：**

```text
WARN No layout: index.html
```

说明 Hexo 没有找到主题所需的布局文件。

### 2. 将 NexT 放入 themes 目录

检查主题目录：

```powershell
Get-ChildItem .\themes -Force
```

发现其中只有 `.gitkeep`，说明 Hexo 默认查找的主题目录中没有实际主题文件。

复制主题：

```powershell
Copy-Item .\node_modules\hexo-theme-next .\themes\next -Recurse
```

修改 Hexo 主题配置：

```powershell
(Get-Content .\_config.yml -Raw) -replace '(?m)^theme:.*$', 'theme: next' | Set-Content .\_config.yml -Encoding utf8
```

**作用：** 将 Hexo 使用的主题名称设置为 `next`，对应 `themes/next` 目录。

重新生成：

```powershell
npx hexo clean
npx hexo generate
```

**结果：** NexT 成功加载，不再出现 `No layout`。

启动预览：

```powershell
npx hexo server
```

### 3. 创建 NexT 独立配置文件

将主题默认配置复制到项目根目录：

```powershell
Copy-Item .\themes\next\_config.yml .\_config.next.yml
```

检查：

```powershell
Test-Path .\_config.next.yml
```

**作用：** 创建独立的 NexT 配置文件，避免直接修改主题源码。

在 `_config.yml` 中补充站点信息：

```yaml
title: 你的博客名称
subtitle: ''
description: ''
keywords:
author: 你的昵称
language: zh-CN
timezone: Asia/Shanghai
```

在 `_config.next.yml` 中检查主题配置：

```powershell
Select-String -Path .\_config.next.yml -Pattern "custom_file_path|scheme:|darkmode:"
```

**结果：** 找到主题自定义样式入口，准备调整博客外观。

### 4. 自定义博客配色

最初尝试通过变量文件修改颜色。

创建文件：

```powershell
New-Item -ItemType Directory -Force .\source\_data | Out-Null
New-Item -ItemType File -Force .\source\_data\variables.styl
```

启用 `_config.next.yml` 中的变量配置：

```yaml
custom_file_path:
  variable: source/_data/variables.styl
```

但第一次修改后，页面颜色没有明显变化。

因此改用直接覆盖 CSS 样式的方式。

创建样式文件：

```powershell
New-Item -ItemType File -Force .\source\_data\styles.styl
```

在 `_config.next.yml` 中启用：

```yaml
custom_file_path:
  variable: source/_data/variables.styl
  style: source/_data/styles.styl
```

将自定义 Stylus 样式写入：

```text
source/_data/styles.styl
```

主要实现：

- 页面背景：低饱和粉灰紫纵向渐变。
- 左侧目录：稍深的灰粉紫。
- 右侧文章：浅粉灰紫。
- 链接：柔和粉紫色。
- 正文：偏灰紫的深色。

重新生成并预览：

```powershell
npx hexo clean
npx hexo generate
npx hexo server
```

**结果：** 自定义配色成功加载。

后来发现代码块的黑色背景与整体配色不协调，暂时保留问题，后续可以单独覆盖代码块样式。

### 5. 恢复默认配色的方法

清空自定义样式文件：

```powershell
Clear-Content .\source\_data\styles.styl
```

重新生成：

```powershell
npx hexo clean
npx hexo generate
npx hexo server
```

由于 NexT 已经配置了 `custom_file_path.style`，所以文件内容会自动参与主题样式构建，不需要额外指定。

### 3. 创建标签页面

在 `source/tags/index.md` 中写入：

重新生成：

```powershell
npx hexo clean

npx hexo server
```

**结果：** 分类、标签页面及导航入口正常。

### 4. 配置站内搜索

检查 NexT 搜索配置：

```powershell
Select-String -Path .\_config.next.yml -Pattern "local_search:"
```

查看配置：

```powershell
Get-Content .\_config.next.yml | Select-Object -Skip 845 -First 25
```

启用本地搜索：

```yaml
local_search:
  enable: true
```

**作用：** 开启 NexT 的本地搜索界面。

原计划安装搜索索引插件：

```powershell
pnpm add hexo-generator-searchdb
```

但再次遇到：

```text
ERR_PNPM_IGNORED_BUILDS
```

于是检查插件：

```powershell
pnpm list hexo-generator-searchdb
```

随后在 `_config.yml` 中添加搜索索引配置：

```yaml
search:
  path: search.xml
  field: post
  content: true
  format: html
```

重新生成：

```powershell
npx hexo clean
npx hexo generate
```

检查索引文件：

```powershell
Test-Path .\public\search.xml
```

**结果：** 返回 `True`，说明搜索索引文件已经生成。

这里需要注意：生成 `search.xml` 和 NexT 搜索界面正常工作是两个不同环节，后续仍需实际测试搜索功能。

### 5. 关闭主题动画

检查动画配置：

```powershell
Select-String -Path .\_config.next.yml -Pattern 'motion:|enable:|async:|transition:'
```

修改：

```yaml
motion:
  enable: false
```

重新生成：


启动预览：


## 四、认识项目结构与博客内容管理

**阶段目标：** 明确 Hexo 的项目结构，建立日常写作和图片管理方式。

### 1. 认识项目结构

```text
F:\blog
│
├── source/
│   ├── _posts/          # 博客文章
│   ├── categories/      # 分类页面
│   ├── tags/            # 标签页面
│   └── _data/           # 自定义样式等资源
│
├── themes/
│   └── next/            # NexT 主题
│
├── public/              # 最终生成的网站
│
├── _config.yml          # Hexo 全局配置
├── _config.next.yml     # NexT 主题配置
├── package.json         # 项目依赖
├── pnpm-lock.yaml       # pnpm 依赖锁定文件
└── .gitignore           # Git 忽略规则
```

核心逻辑：

- `source/`：内容来源，存放文章、页面及相关资源。
- `themes/`：外观来源，存放主题。
- `public/`：最终生成的静态网站。
- `_config.yml`：控制 Hexo 全局行为。
- `_config.next.yml`：控制 NexT 主题行为。

### 2. 创建博客文章

```powershell
npx hexo new post "Java 异常处理"
```

Hexo 会在 `source/_posts/` 中创建 Markdown 文件。

文章示例：

```yaml
---
title: Java 异常处理
date: 2026-10-29 22:30:00
categories:
  - Java
tags:
  - 异常处理
  - Java基础
---

## throw 和 throws

`throw` 用于主动抛出异常。

`throws` 用于在方法声明中标注可能抛出的异常。
```

**作用：**

- `title`：文章标题。
- `date`：发布时间。
- `categories`：文章分类。
- `tags`：文章标签。
- 正文：使用标准 Markdown 编写。

### 3. 配置文章资源文件夹

发现文章中的图片无法正常显示。

先检查：

```powershell
Select-String -Path .\_config.yml -Pattern '^post_asset_folder:'
```

原配置：

```yaml
post_asset_folder: false
```

修改为：

```yaml
post_asset_folder: true
```

**作用：** 开启文章资源文件夹机制，使每篇文章可以拥有独立的资源目录。

### 4. 排查图片生成问题

先检查文章内容：

```powershell
Get-Content .\source\_posts\hello-next\hello-next.md
```

检查文章是否被 Hexo 识别：

```powershell
npx hexo list post
```

**结果：** 文章已经被 Hexo 识别。

检查生成的 HTML：

```powershell
Get-ChildItem .\public -Recurse -Filter index.html |
Select-Object FullName
```

发现文章生成路径：

```text
public/
└── 2026/
    └── 10/
        └── 29/
            └── hello-next/
                └── hello-next/
                    └── index.html
```

检查图片是否生成：

```powershell
Get-ChildItem .\public -Recurse -Filter image.png |
Select-Object FullName
```

发现图片没有生成，说明文章生成和图片生成需要分别检查。

### 5. 建立正确的图片资源结构

最终采用：

```text
source/
└── _posts/
    └── hello-next/
        ├── hello-next.md
        └── hello-next/
            └── image.png
```

也就是：

- 第一层 `hello-next/`：文章所在目录。
- `hello-next.md`：文章本体。
- 第二层 `hello-next/`：文章关联的资源文件夹。
- `image.png`：图片资源。

重新生成：

```powershell
npx hexo clean
npx hexo generate
```

检查：

```powershell
Get-ChildItem .\public -Recurse -Filter image.png |
Select-Object FullName
```

**结果：** 图片成功生成到 `public` 对应的文章目录。

### 6. 解决 Markdown 图片引用问题

最初尝试：

```markdown
![image](./hello-next/image.png)
```

发现生成后的 HTML 出现：

```html
<img src="/./hello-next/image.png" alt="image">
```

图片引用地址不正确。

曾尝试 Hexo 图片标签：

```text
{% asset_img image.png image %}
```

最终确认可以通过 Markdown 渲染器的资源配置，保留普通 Markdown 图片语法。

在 `_config.yml` 中配置：

```yaml
post_asset_folder: true

marked:
  prependRoot: true
  postAsset: true
```

文章中使用：

```markdown
![image](image.png)
```

**作用：**

- `post_asset_folder: true`：启用文章关联资源文件夹。
- `prependRoot: true`：为图片资源路径添加站点根路径。
- `postAsset: true`：让 Markdown 渲染器按照文章资源目录处理图片引用。

检查 Markdown 渲染器：

```powershell
pnpm list hexo-renderer-marked
```

结果为：

```text
hexo-renderer-marked@7.0.1
```

检查生成后的 HTML：

```powershell
Select-String -Path .\public\2026\10\29\hello-next\hello-next\index.html -Pattern 'image.png'
```

得到：

```html
<img src="/2026/10/29/hello-next/hello-next/image.png" alt="image">
```

**结果：** 图片 URL 与生成后的实际文件位置一致。

最后启动本地服务器：

```powershell
npx hexo server
```

浏览器刷新后图片正常显示。

### 7. 明确 generate 与 server 的区别

```powershell
npx hexo clean
npx hexo generate
npx hexo server
```

三个命令的职责：

| 命令 | 作用 |
|---|---|
| `hexo clean` | 清理之前生成的静态文件 |
| `hexo generate` | 根据文章、配置和主题生成静态网页 |
| `hexo server` | 启动本地服务器，供浏览器预览 |

注意：`generate` 负责生成文件，`server` 负责提供本地预览服务。两者不是同一件事。

### 8. 确定日常文章迁移方案

为了方便以后将 Typora 笔记迁移到 Hexo，采用统一的目录约定：

```text
一篇文章/
├── article.md
└── article/
    ├── image1.png
    └── image2.png
```

迁移时：

1. 在 `source/_posts/` 中创建文章目录。
2. 将 Markdown 文件放入文章目录。
3. 创建与 Markdown 文件同名的资源子目录。
4. 将图片放入资源子目录。
5. 保留普通 Markdown 图片引用。

这样可以让 Typora 和 Hexo 尽量共用标准 Markdown 写作习惯，后续可以通过 AI 或自动化脚本完成目录迁移。

## 五、Git 本地版本管理与 GitHub 远程连接

**阶段目标：** 将本地 Hexo 项目纳入 Git 管理，并推送到 GitHub。

### 1. 初始化 Git 仓库

```powershell
git init
```

**作用：** 在当前博客目录创建本地 Git 仓库。

### 2. 绑定 GitHub 远程仓库

```powershell
git remote add origin git@github.com:zigyr/zigyr.github.io.git
```

**作用：** 将本地仓库与 GitHub 上的远程仓库关联。

检查：

```powershell
git remote -v
```

### 3. 检查 SSH 连接

```powershell
ssh -T git@github.com
```

返回：

```text
Hi zigyr! You've successfully authenticated,
but GitHub does not provide shell access.
```

**结果：** SSH 身份验证成功，可以使用 SSH 方式推送代码。

### 4. 检查 Git 忽略规则

```powershell
Get-Content .gitignore
```

**作用：** 检查哪些文件不会被 Git 追踪。

主要避免提交：

- `node_modules/`：项目依赖。
- `public/`：生成的静态网页。
- 其他临时文件和缓存。

查看工作区：

```powershell
git status --short
```

### 5. 首次提交

```powershell
git add .
git commit -m "Initial Hexo blog setup"
```

**作用：**

- `git add .`：将当前目录下未忽略的文件加入暂存区。
- `git commit`：将暂存区内容保存为本地版本记录。

### 6. 推送到 GitHub

```powershell
git branch -M main
git push -u origin main
```

**作用：**

- `git branch -M main`：将当前分支名称统一为 `main`。
- `git push -u origin main`：将本地提交推送到远程仓库，并建立分支跟踪关系。

**结果：** GitHub 仓库已经拥有本地 Hexo 项目的代码。

## 六、解决 NexT 主题在 GitHub Actions 中无法加载的问题

**阶段目标：** 让 GitHub 云端构建环境能够正确获取 NexT 主题。

### 1. 检查部署错误

GitHub Actions 报错：

```text
Error: The next theme could not be found.
```

**原因：** GitHub Actions 构建环境找不到 NexT 主题。

首先检查主题目录：

```powershell
git status --short --ignored themes
```

检查本地主题：

```powershell
Get-ChildItem .\themes -Force
```

检查是否存在独立 Git 仓库：

```powershell
Test-Path .\themes\next\.git
```

返回：

```text
False
```

说明它不是独立 Git 仓库。

检查主题文件：

```powershell
Get-ChildItem .\themes\next -Force |
Select-Object -First 10 Name, Mode
```

发现主题目录内容完整。

### 2. 检查 Git 是否追踪主题文件

```powershell
git ls-files themes/next
```

**结果：** 本地 Git 已经追踪主题文件。

继续检查远程分支：

```powershell
git ls-tree -r --name-only origin/main themes/next
```

**结果：** 远程 `main` 分支也包含 NexT 主题文件。

因此排除主题没有推送到 GitHub 的可能。

### 3. 检查 GitHub Actions 工作流

```powershell
Get-ChildItem .github -Recurse -File |
Select-Object FullName
```

**结果：** `.github` 目录中只有 `dependabot.yml`，没有 Hexo 部署工作流。

这说明 GitHub 还没有明确的自动构建和部署流程。

## 七、建立 GitHub Actions 自动部署工作流

**阶段目标：** 让 GitHub 在收到代码更新后，自动安装依赖、构建 Hexo 并发布网页。

### 1. 创建工作流目录

```powershell
New-Item -ItemType Directory -Force .github\workflows
```

创建工作流文件：

```powershell
notepad .github\workflows\deploy.yml
```

写入：

```yaml
name: Deploy Hexo to GitHub Pages

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 10

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Prepare NexT theme
        run: |
          if [ ! -d themes/next/layout ]; then
            mkdir -p themes/next
            cp -r node_modules/hexo-theme-next/. themes/next/
          fi

      - name: Generate Hexo site
        run: |
          pnpm exec hexo clean
          pnpm exec hexo generate

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./public

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

### 2. 理解工作流的执行逻辑

整个工作流分为两个 Job。

**Job 1：build，构建网站**

执行顺序：

1. `Checkout repository`：获取 GitHub 仓库代码。
2. `Setup pnpm`：配置 pnpm。
3. `Setup Node.js`：配置 Node.js 22。
4. `Install dependencies`：根据锁定文件安装项目依赖。
5. `Prepare NexT theme`：检查主题目录，必要时从 `node_modules` 补充主题文件。
6. `Generate Hexo site`：执行 Hexo 清理和静态网页生成。
7. `Upload Pages artifact`：将 `public` 目录上传为 GitHub Pages 部署产物。

**Job 2：deploy，部署网站**

1. 等待 `build` 完成。
2. 使用 `actions/deploy-pages@v4` 发布构建产物。
3. 将网站部署到 GitHub Pages。

两者之间的关系：

```text
GitHub 仓库收到 push
        │
        ▼
      build
        │
        ▼
  安装项目依赖
        │
        ▼
  准备 NexT 主题
        │
        ▼
  Hexo generate
        │
        ▼
  上传 public 目录
        │
        ▼
      deploy
        │
        ▼
  GitHub Pages 发布
        │
        ▼
  https://zigyr.github.io
```

### 3. 提交工作流文件

检查文件：

```powershell
Get-Content .github\workflows\deploy.yml
```

提交并推送：

```powershell
git add .github/workflows/deploy.yml
git commit -m "Add GitHub Pages deployment workflow"
git push
```

**结果：** 推送后，GitHub Actions 自动触发部署工作流。

## 八、解决 GitHub Pages 发布来源冲突，完成部署

**阶段目标：** 让 GitHub Pages 使用 Actions 部署，而不是另一套构建机制。

### 1. 检查 Actions 构建结果

GitHub Actions 出现：

```text
pages build and deployment / build (dynamic)
Failing after 18s
```

此时不能直接认为 Hexo 网站没有部署成功。

进入仓库：

```text
Settings → Pages
```

找到：

```text
Build and deployment
```

检查当前发布来源。

### 2. 修改 GitHub Pages 发布模式

将：

```text
Deploy from a branch
```

修改为：

```text
GitHub Actions
```

**作用：** 明确指定 GitHub Pages 使用自定义 Actions 工作流完成构建和发布。

### 3. 检查最终访问效果

访问：

```text
https://zigyr.github.io
```

发现：

- 网站已经可以正常访问。
- NexT 主题加载正常。
- 图片正常显示。
- 页面与本地预览基本一致。

但 Actions 页面仍然存在失败记录。

进一步检查发现，报错涉及 Jekyll。

**最终排查结果：** 之前遗留的 GitHub Pages 分支部署构建流程仍在运行，与 Hexo 自定义 Actions 部署流程产生了混淆。

最终通过将 GitHub Pages 的发布来源明确设置为 `GitHub Actions`，解决了部署模式冲突。

# 最终部署流程总结

整个项目可以归纳为以下几个环节：

| 阶段 | 核心任务 | 主要工具 |
|---|---|---|
| 1. 环境准备 | 创建仓库、安装 Hexo、初始化项目 | npm、Hexo |
| 2. 主题配置 | 安装 NexT、修改主题和样式 | pnpm、Stylus、YAML |
| 3. 功能配置 | 菜单、分类、标签、搜索、动画 | NexT、Hexo |
| 4. 内容管理 | Markdown、图片资源、文章生成 | Markdown、Hexo |
| 5. 版本管理 | 初始化仓库、提交、远程推送 | Git、GitHub |
| 6. 主题排错 | 解决云端找不到 NexT 的问题 | Git、GitHub |
| 7. 自动化构建 | 安装依赖、生成网页、上传产物 | GitHub Actions |
| 8. 自动部署 | 配置 Pages 发布来源、完成上线 | GitHub Pages |
